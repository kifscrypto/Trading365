# T365 Desk v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and package a local-first Windows Electron application that runs the T365 scanner and presents live market data, news, imported calendars, alerts, and local ownership controls without the hosted T365 service.

**Architecture:** Electron main-process TypeScript owns public API access, scanner jobs, local JSON persistence, notifications, and native dialogs. A narrow context-isolated preload exposes `window.t365`; a static sandboxed renderer implements the approved five-screen workstation without runtime dependencies.

**Tech Stack:** Electron, TypeScript, Node.js public-fetch APIs, HTML/CSS/vanilla JavaScript, Electron Builder, pnpm.

**Spec:** `docs/superpowers/specs/2026-11-01-t365-desktop-v1-design.md`

## Global Constraints

- Work only in `C:\dev\trading365\desktop` plus this design/plan; do not modify the hosted Next.js application.
- Do not run dependency installation or builds in the OneDrive copy.
- Use direct OKX/Hyperliquid public data, CoinDesk/Cointelegraph RSS, CoinGecko global data, and Alternative.me Fear & Greed; never substitute demo data for failed live sources.
- No exchange keys, account backend, activation requirement, remote renderer content, Node integration, or external Electron navigation.
- Main process owns network and persistence; writes are serialized and atomic; overlapping jobs are prevented.
- Candidates must be distinguished from fired entries. Preserve last-good data and source timestamps on failures.
- No permanent test files are added to this test-less repository; use inline smoke assertions, typecheck, live workflows, and packaged-app verification.

## Review Focus

- Empty or failed first launch: show an actionable empty/degraded state rather than blank panels or fabricated data; exercise in Task 4.
- Provider failure after a successful refresh: retain cached content and mark it stale; exercise in Task 5.
- Duplicate scan/entry timers: prevent overlapping jobs and duplicate open signals; assert in Task 3 smoke checks.
- Malformed RSS/ICS and unsafe article URLs: ignore bad records and reject non-HTTP(S) or unexpected hosts; exercise in Tasks 3 and 5.
- JSON corruption or interrupted writes: preserve a recoverable error and avoid silently destroying the local document; exercise in Task 1 smoke checks.
